Cloudflare Tunnel 設定筆記

把本機服務(localhost:8080)透過 Cloudflare 對外,免開 port、免公開 IP

最後更新 2026-09-17 · 真實踩坑紀錄 · 約 30 分鐘從零到上線

這篇是我把 https://calc.sunnyq.idv.tw 跑起來的全過程。從「.idv.tw 到底能不能用 Cloudflare」、「NS 怎麼改」、「Hinet DNS 後台藏在哪」、「tunnel config 怎麼寫」、「DNS record 的 Target 要填什麼」一路到最後通車。每一個我都親自撞牆過。

成果

✅ 最終狀態
  • 本機 Flask app 跑在 localhost:8080
  • 對外網址:https://calc.sunnyq.idv.tw
  • Cloudflare 自動 HTTPS + CDN + DNS
  • 免費,無公開 IP,家裡防火牆不用打洞

TL;DR — 30 分鐘流程

  1. 確認 domain 在 Cloudflare 支援的 TLD 白名單(我用的是 .idv.tw,2024 後支援)
  2. Cloudflare 後台 Add a site → 填 domain → 拿兩組 NS(像 xxx.ns.cloudflare.com)
  3. 到原註冊商(Hinet)後台把 NS 改到 Cloudflare 那兩組
  4. 等 1-24 小時讓 Cloudflare 驗證 NS(propagation)
  5. 裝 cloudflared,建 tunnel,寫 config,把 DNS 接到 tunnel
  6. 本機服務跑起來 + tunnel 跑起來 → 對外通了

Step 0 — Domain 跟 TLD 的選擇

Cloudflare 不是所有 TLD 都收。常見問題是「便宜的 TLD 都不收」。

TLDCloudflare備註
.com / .net / .org✅穩,首年 $9.15 USD
.co.uk / .uk✅~$6 USD/年,英國/歐洲
.dev / .app / .io✅偏貴,適合科技
.tw / .com.tw / .org.tw✅NT$800/年,個人/公司皆可
.idv.tw✅NT$450/年(自然人限定),2024 後支援
.xyz / .tech / .studio✅首年超便宜,續費會漲
⚠️ 一個重要發現:我之前看網路上資料,以為 .idv.tw 不能接 Cloudflare(因為是自然人 TLD + TWNIC 政策)。但實測 2026 年已經可以了 — TWNIC 開放了自訂 NS,Cloudflare 也收。所以別輕信舊文件,先試再說。

Step 1 — Cloudflare Add a site

到 dash.cloudflare.com,點 Add a site,輸入你的 domain(我用 sunnyq.idv.tw)。

❌ 撞牆點 1:打錯網域名稱

我原本打成 sunnq.idv.tw(6 字母,沒註冊),Cloudflare 一開始會讓你加,然後一直 pending — 因為那個網域根本不存在。請確認你打的是真正註冊的網域。

驗證方式:nslookup sunnyq.idv.tw 8.8.8.8 看有沒有回應。

成功會進入「選方案」頁面(免費方案就夠),然後 Cloudflare 給你兩組 NS:

amber.ns.cloudflare.com
osmar.ns.cloudflare.com

記下這兩組,下一步要去你的註冊商那邊改。

Step 2 — 改 NS 到 Cloudflare

到原註冊商後台(我用 Hinet),找到「網域名稱管理」→ 編輯 NS。

Hinet 後台路徑

不容易找,藏在幾層後面:

  1. member.hinet.net → 登入
  2. 我的服務 → 網域名稱 → 找到你要編輯的網域
  3. 進到該網域的「狀態」頁
  4. 找「DNS 主機」或「NS 紀錄」的編輯入口
⚠️ Hinet 介面坑:Hinet 後台的 NS 編輯欄位看起來像要填 IP,但 NS 是主機名,不是 IP。要填的是 amber.ns.cloudflare.com 這種,不是 IP 位址。如果你看到欄位寫「IP Address」,可能你看錯欄位了。

把 NS 改成:

原本:admns1.hinet.net + admns2.hinet.net
改成:amber.ns.cloudflare.com + osmar.ns.cloudflare.com

存檔後,回到 Cloudflare Overview 頁,會看到「Waiting for your registrar to propagate your new nameservers」。

Step 3 — 等 Cloudflare 驗證 NS

這一步只能等。Cloudflare 會持續檢查,有時候 1 小時,有時候要 24 小時。

⚠️ pending 不要緊張:過程中 Cloudflare 會給一堆警告:
  • 「Visitors cannot reach www.xxx」 — 因為你還沒加 DNS records
  • 「Email cannot reach ...」 — 因為你沒設 MX
  • 「is pending until you complete ...」 — NS 還沒生效

這些都是「提示」,不是「錯誤」,等 NS 生效就會消失。

驗證 NS 是否生效:

nslookup -type=ns sunnyq.idv.tw 8.8.8.8

應該看到 Cloudflare 的 NS,不是 Hinet 的。

Step 4 — 裝 cloudflared

cloudflared 是 Cloudflare 的官方 tunnel daemon,Windows / macOS / Linux 都有。

Windows 用 winget 裝最快:

winget install Cloudflare.cloudflared

裝完關掉再開新 PowerShell,驗證:

cloudflared --version

應該印出版本號。

Step 5 — 登入 Cloudflare

cloudflared tunnel login

會自動開瀏覽器,選你的 Cloudflare account → 授權 → PowerShell 印 You have successfully logged in.

產出 ~/.cloudflared/cert.pem。

⚠️ 如果已經有 cert.pem:會跳錯「existing certificate, login would overwrite」。這代表你之前跑過 login,直接用現有的就行,不用刪。

Step 6 — 建 tunnel

cloudflared tunnel create calc-tunnel

輸出會給你:

Tunnel credentials written to C:\Users\joe\.cloudflared\<UUID>.json
Created tunnel calc-tunnel with id <UUID>

把 UUID 記下來,下一步會用到。

Step 7 — 把 DNS 接到 tunnel

cloudflared tunnel route dns calc-tunnel calc.sunnyq.idv.tw

會在 Cloudflare DNS 自動加一筆 CNAME:

calc.sunnyq.idv.tw → <UUID>.cfargotunnel.com
❌ 撞牆點 2:訊息裡奇怪的「.sunnq.idv.tw」

輸出可能會寫:

Added CNAME calc.sunnyq.idv.tw.sunnq.idv.tw

看起來很怪,但 Cloudflare 內部其實存的是正確的 calc.sunnyq.idv.tw。去 Dashboard 看實際 record 就會發現沒問題。

Step 8 — 寫 config.yml

位置:%USERPROFILE%\.cloudflared\config.yml

tunnel: 8db00f0d-dd1b-4c80-885b-a8099b5c68a6
credentials-file: C:\Users\joe\.cloudflared\8db00f0d-dd1b-4c80-885b-a8099b5c68a6.json

ingress:
  - hostname: calc.sunnyq.idv.tw
    service: http://localhost:8080
  - service: http_status:404

把 <UUID> 換成真的 UUID。

❌ 撞牆點 3:舊 config 引用不存在的 UUID

如果你之前有建過 tunnel,可能 config.yml 已經存在,內容是別的 UUID + 不存在的 .json。會跑不起來。

確認 UUID 跟 .json 檔名對得起來:

ls ~/.cloudflared/

Step 9 — 跑起來

需要兩個 process:

Process 1 — Flask app(本機服務)

cd "C:\Users\joe\Documents\GitHub\calc-password-tool\server"
python app.py

Process 2 — cloudflared tunnel

cloudflared tunnel run calc-tunnel

成功會印:

INF Connection established connIndex=0
INF Connection established connIndex=1
...

Step 10 — 驗證

瀏覽器打開 https://calc.sunnyq.idv.tw。

如果通了 — 恭喜 🎉

⚠️ 第一次可能看到的錯誤
錯誤原因
1033DNS CNAME 沒對應到對的 tunnel UUID
530tunnel 沒在跑,或 DNS 還沒生效
502 / 504tunnel 跑著但 Flask 沒跑
一直轉圈SSL 憑證還在頒發(等 1-2 分鐘)

常見問題排除

Q: Cloudflare Tunnel UUID 怎麼查?

cloudflared tunnel info calc-tunnel

輸出第一行 ID: 後面就是 UUID。

Q: 怎麼確認 tunnel 在不在?

cloudflared tunnel info calc-tunnel
# 看有沒有 CONNECTOR ID 那行,有 = 在線
# 看 EDGE 欄位有沒有台北/高雄 edge 名字(2xtpe01 之類)

如果 does not have any active connection 表示 tunnel 沒跑,要 tunnel run。

Q: Tunnel UUID 對了但還是不通?

  1. 去 Cloudflare Dashboard → DNS → Records → 看 calc 那筆的 Target
  2. 確認 Target 是 <UUID>.cfargotunnel.com,不是字面 <uuid>.cfargotunnel.com(沒換掉)
  3. 確認 Proxy 是橘色「Proxied」

Q: NS 已改但 Cloudflare 還是 pending?

  1. 用 nslookup -type=ns <your-domain> 8.8.8.8 確認 NS 真的指向 Cloudflare
  2. 如果還是 Hinet 的 NS,代表註冊商那邊沒真的存到
  3. 確認 Hinet 後台的「DNS 主機」欄位真的顯示 Cloudflare 主機名

Q: cert.pem 是什麼?可以刪嗎?

cert.pem 是 cloudflared tunnel login 產的帳號憑證。不要刪,刪了 tunnel 就連不到 Cloudflare。

進階:跑成 Windows Service(開機自動起)

不想每次手動開 PowerShell,用 NSSM 把 tunnel 跟 Flask 註冊成 Windows service:

# 下載 NSSM: https://nssm.cc/download

# Flask
nssm install CalcPasswordFlask "C:\Python311\python.exe" "C:\Users\joe\Documents\GitHub\calc-password-tool\server\app.py"
nssm set CalcPasswordFlask AppDirectory "C:\Users\joe\Documents\GitHub\calc-password-tool\server"
nssm start CalcPasswordFlask

# Tunnel
nssm install CalcTunnel "C:\Users\joe\cloudflared.exe" "tunnel run calc-tunnel"
nssm start CalcTunnel

之後重開機,兩個 service 自動起,domain 一直在線。

Quick Tunnel(免 domain,隨機網址)

如果只是想趕快 demo、不想花錢買 domain,Cloudflare 有「quick tunnel」模式:

cloudflared tunnel --url http://localhost:8080

輸出給你一個 https://random-words-1234.trycloudflare.com 網址,馬上可用,不用 Cloudflare 帳號、不用網域、不用任何設定。

⚠️ Quick tunnel 的網址每次啟動會變。要固定就要買 domain + named tunnel。

整體架構圖

[瀏覽器]
   ↓ https://calc.sunnyq.idv.tw
[Cloudflare Edge Network] ← CDN + WAF + SSL + DNS
   ↓ (tunnel 加密連線,主動外連)
[cloudflared] ← 你機器上的 daemon
   ↓ http://localhost:8080
[Flask app] ← 你的服務

重點:

  • 瀏覽器 → Cloudflare:走公開 HTTPS,Cloudflare 處理 SSL
  • Cloudflare → cloudflared:Cloudflare 主動連到你機器的 cloudflared(出站),不是入站
  • cloudflared → Flask:localhost HTTP,不對外
  • 你家的防火牆不用開任何 port,cloudflared 自動 outbound 連到 Cloudflare
