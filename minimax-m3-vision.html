🖼️ 圖片理解

給定 URL／本地檔路徑，能讀內容、描述場景、識別物件、回答關於圖片的問題。 observed

vidya_analyze 工具呼叫即觸發；vision-capable model 時直接讀圖，否則 fallback 給輔助 vision 模型。

📐 多解析度支援

實測過 832×1248 直式 fashion 圖（這頁生成 demo 的 size），能完整識別。 observed

具體最大解析度 / token 上限未公開。

🌐 多圖輸入

支援同時理解多張圖（vision_analyze 接受 list）。 observed

單次最多幾張未公開。

💬 中英文圖片混合

圖中含中文文字（截圖、IG post、雜誌）能讀出主要內容。 observed

OCR 完整度見下「限制」區。

⚠️ 限制與坑（observed）

限制細節影響來源
OCR 非強項 圖中細小文字（< 12px）、手寫字、表格內文容易漏字 / 讀錯 廣告圖、細節高的法律條款不適合純靠 vision observed
長文截圖 給一整頁文章截圖，會抓到開頭但中段常「(screenshot removed)」被截斷 多頁連續截圖解析不穩；建議改用 PDF 工具 observed
連續 vision 呼叫會拒絕 短時間內多次 vision_analyze 會出現「screenshot removed」 批量抽幀分析時要分批、自我節流 observed
不擅長計數 / 數字精算 問「圖中有幾個人」/「這條 K 線幾 %」會給模糊答案 數據導向任務要用 OCR + 外部工具 observed
時間戳 / 中英混排 圖中混雜簡繁、英文夾雜中文，有時理解錯誤 對話截圖、code 截圖偶爾誤判 observed
不支援影片原生 影片要靠 ffmpeg 抽幀再分析，不是真原生 video 時序理解弱、字幕要靠 OCR observed

🧪 最佳實務（joe 偏好的使用方式）

場景推薦做法
讀截圖 直接丟 vision_analyze，要求「條列 + 引用原文」，不靠 summary
視覺驗證 UI 明確指定「只看 X 區塊、忽略 Y、找 Z 元素」— 不要問「這看起來怎樣」
圖生圖比較 同一張圖丟兩次比對，看 vision 對細節（手、材質、文字）的掌握度
影片分析 先 ffmpeg 抽關鍵幀（去重後），再 vision_analyze；不要一次丟連續幀
PDF / 報告 走 pdf 工具（pdfminer.six），不要先轉圖再 vision
案情 / 合約細節 圖 + 文字 prompt 並用：「圖中提到 X 的部分，請逐字引用」

❓ 還沒驗證的（unknown）

  • 具體最大支援解析度（width × height 上限） unknown
  • 單張圖的 token 計價 unknown
  • 多圖混合時的注意力分配 unknown
  • PDF 多頁圖（連續頁）處理行為 unknown
  • 輔助 vision fallback 模型是誰（設定裡沒指明） unknown
  • 對外圖床（imgur / i.imgur）vs 本地檔的 backend 行為差異 unknown
